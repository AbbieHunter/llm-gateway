# LLM Gateway 用户故事地图（User Story Map）

> 版本：v0.2（评审回写）
> 日期：2026-07-23
> 目的：将 `PRD.md` / `PRODUCT_DESIGN.md` / `../technical/ARCHITECTURE.md` 中的功能需求拆解为**可独立交付、可测试、可排期**的用户故事，作为 M0–M4 的开发任务单元。
> 关联：PRD §4 功能需求、产品设计核心流程、架构里程碑 M0–M4。
> v0.2 变更（评审会决议）：新增 US-M1-00（初始管理员引导）、US-M1-14（登出）；US-M2-03/US-M3-07 升 Must；US-M3-10 拆 10a/10b/10c；新增「MVP 显式不做」清单。

---

## 阅读说明

- **格式**：`作为 [角色]，我希望 [行为]，以便 [价值]`；每条配**验收标准（AC）**与**优先级 / 里程碑 / 依赖**。
- **优先级（MoSCoW）**：Must（MVP 必做）/ Should（重要）/ Could（可选）/ Won't（本期不做）。
- **里程碑**：M0 骨架验证 → M1 账号/VK/路由/控制台基础 → M2 流式/额度/用量 → M3 配额感知路由/缓存/报表 → M4 可选。
- **依赖**：被依赖的故事需先完成，避免开发空转。
- 角色缩写：**Admin**=管理员，**User**=普通用户（开发者），**GW**=网关（系统侧），**Ops**=运维。

## M0 · 骨架验证

### US-M0-01 · 统一入口非流式调用
- **作为** User（开发者）
- **我希望** 把应用的 `base_url` 指向网关、用单个 provider 完成一次非流式对话
- **以便** 验证"改一个 base_url 而非改代码"的统一入口成立
- **验收标准**
  - `POST /v1/chat/completions`（`stream=false`）经 LiteLLM 调通单 provider
  - 请求/响应严格 OpenAI 兼容格式
  - 用官方 OpenAI SDK 仅改 `base_url` 即可对话，无需改业务代码
- **优先级**：Must · **里程碑**：M0 · **依赖**：无

### US-M0-02 · 控制台页面可加载
- **作为** Admin
- **我希望** 打开浏览器根路径能加载管理控制台 SPA 静态资源
- **以便** 后续在此管理 Key/Provider/路由（本阶段功能可未全）
- **验收标准**
  - FastAPI `StaticFiles` 挂载前端构建产物，访问 `/` 返回 SPA
  - 页面骨架（导航/布局）可渲染，未实现功能可置占位
- **优先级**：Must · **里程碑**：M0 · **依赖**：无

### US-M0-03 · 一键本地启动
- **作为** Ops
- **我希望** `docker-compose up` 起网关 + Redis
- **以便** 本地零配置运行
- **验收标准**
  - 单命令启动成功，网关健康检查（`/healthz` 或等价）通过
  - Redis 连通，日志无致命错误
- **优先级**：Must · **里程碑**：M0 · **依赖**：无

## M1 · 账号 / RBAC / 虚拟 Key / 多 Provider / 路由 / 控制台基础

### 初始引导

### US-M1-00 · 首次启动引导创建初始管理员
- **作为** Ops（或首次部署者）
- **我希望** 在系统尚无任何账号时，通过环境变量或 setup 命令创建首个 admin 账号
- **以便** 有初始入口登录并继续创建其他账号（避免"无人能登录"的死锁）
- **验收标准**
  - 仅当 accounts 表为空时引导生效；已有账号则不触发
  - 支持 `BOOTSTRAP_ADMIN_PASSWORD`（或等价 setup 命令）设定初始口令
  - 引导创建的账号角色=admin，可立即登录
  - 不暴露公开注册页
- **优先级**：Must · **里程碑**：M1（最先）· **依赖**：无

### 账号与角色

### US-M1-01 · 账号登录
- **作为** Admin/User
- **我希望** 用用户名 + 口令登录控制台获取会话
- **以便** 进入对应权限的管理界面
- **验收标准**
  - 登录接口校验口令哈希，成功后发放会话凭证（JWT/签名 cookie）
  - 错误口令返回明确错误；会话有合理过期
- **优先级**：Must · **里程碑**：M1 · **依赖**：US-M0-02

### US-M1-02 · 创建账号与分配角色
- **作为** Admin
- **我希望** 创建新账号并分配 `admin` / `user` 角色
- **以便** 控制谁可使用与配置网关
- **验收标准**
  - 账号管理页可新建（用户名、角色、初始口令）
  - 口令以哈希存储，不落明文
  - 仅 Admin 可见/可操作账号管理
- **优先级**：Must · **里程碑**：M1 · **依赖**：US-M1-01

### US-M1-03 · 禁用账号 / 改角色
- **作为** Admin
- **我希望** 禁用某账号或修改其角色
- **以便** 管理权限与回收
- **验收标准**
  - 禁用后该账号会话失效、无法登录与调 API
  - 角色变更即时生效于后续请求鉴权
- **优先级**：Must · **里程碑**：M1 · **依赖**：US-M1-02

### US-M1-04 · 普通用户受限视图
- **作为** User
- **我希望** 登录后只看到自身 Key 与用量，无管理配置入口
- **以便** 不越权操作
- **验收标准**
  - 左侧导航隐藏 Provider/路由/账号管理菜单（UX 层）
  - 仅展示自身相关视图
- **优先级**：Must · **里程碑**：M1 · **依赖**：US-M1-01

### RBAC 强制（后端真相源）

### US-M1-05 · 后端按角色 + 所有权过滤
- **作为** GW（系统）
- **我希望** 对所有 `/api/*` 请求按角色 + `owner_account_id` 强制过滤
- **以便** 即使前端隐藏菜单，User 直调 API 也拿不到他人数据（防越权）
- **验收标准**
  - User 请求他人 Key / 全局报表被拒绝（403/空结果）
  - Admin 可访问全部
  - 该逻辑在服务端，不依赖前端
- **优先级**：Must · **里程碑**：M1 · **依赖**：US-M1-01 · **测试重点**：越权用例必覆盖

### 虚拟 Key

### US-M1-06 · 创建虚拟 Key
- **作为** Admin
- **我希望** 为某账号创建虚拟 Key 并设置可选每日 token 额度、默认启用
- **以便** 下发给开发者接入并控制成本风险
- **验收标准**
  - 接收 name、owner_account_id、daily_tokens(可空)、enabled
  - 入库仅存 SHA-256 哈希；明文仅返回一次
  - 创建成功页展示明文 + 复制按钮 + 警告提示
- **优先级**：Must · **里程碑**：M1 · **依赖**：US-M1-01, US-M1-05

### US-M1-07 · Key 列表与掩码查看
- **作为** Admin
- **我希望** 列表/查看虚拟 Key（掩码、状态、额度、所属账号）
- **以便** 掌握已发放情况
- **验收标准**
  - Key 掩码显示（如 `sk-****1234`）
  - 显示状态徽标（启用/禁用）、今日已用/剩余（M2 后才有数据）
- **优先级**：Must · **里程碑**：M1 · **依赖**：US-M1-06

### US-M1-08 · Key 启用 / 禁用 / 删除
- **作为** Admin
- **我希望** 启用、禁用、删除虚拟 Key
- **以便** 回收或应急
- **验收标准**
  - 禁用后该 VK 调用被拒
  - 删除有二次确认弹窗并显示影响范围
- **优先级**：Must · **里程碑**：M1 · **依赖**：US-M1-06

### US-M1-09 · 重置 Key
- **作为** Admin
- **我希望** 重置某 Key（旧失效、生成新明文）
- **以便** 泄露后安全轮换
- **验收标准**
  - 重置后旧 VK 立即失效，新明文仅返回一次
  - 历史用量归属不变（按 vk_id 关联）
- **优先级**：Should · **里程碑**：M1 · **依赖**：US-M1-06

### Provider 配置

### US-M1-10 · 配置 Provider
- **作为** Admin
- **我希望** 在控制台配置 provider（env 引用名、权重、启停）
- **以便** 接入多家模型
- **验收标准**
  - 仅填环境变量名（如 `OPENAI_API_KEY`），不填真实 key
  - 启停切换即时生效（重启网关后生效，界面须提示"需重启"）
  - 配置存 DB（控制台管理），YAML 仅作首次 seed
- **优先级**：Must · **里程碑**：M1 · **依赖**：US-M1-01

### 路由别名

### US-M1-11 · 创建路由别名
- **作为** Admin
- **我希望** 新建路由别名、排序候选 provider、选 failover/weighted 策略
- **以便** 定义"一组可切换的模型"
- **验收标准**
  - 别名编辑页：候选 provider 有序列表（列表首项=首选，后续=fallback 顺序）
  - 策略选择 failover / weighted（cost 为 Phase 2）
  - `GET /v1/models` 返回该别名
- **优先级**：Must · **里程碑**：M1 · **依赖**：US-M1-10

### US-M1-12 · 按别名路由
- **作为** User（开发者）
- **我希望** 用 VK 调某别名时网关按策略路由到候选 provider
- **以便** 透明切换、无需改业务代码
- **验收标准**
  - 请求体 `model` 填别名即可；网关解析到候选 provider
  - failover 按序、weighted 按权重
- **优先级**：Must · **里程碑**：M1 · **依赖**：US-M1-06, US-M1-11

### US-M1-13 · 跳过不可用 Provider
- **作为** GW
- **我希望** 路由时跳过被标记 `down` / `degraded` 的 provider
- **以便** 避开已故障节点
- **验收标准**
  - 健康状态存 Redis，路由前过滤
  - 候选全不可用进入 fallback 末端处理（M3 的 502）
- **优先级**：Must · **里程碑**：M1 · **依赖**：US-M1-11

### 会话

### US-M1-14 · 登出与会话失效
- **作为** Admin/User
- **我希望** 主动登出控制台，使当前会话立即失效
- **以便** 在共享/公共机器上登录后不留活会话
- **验收标准**
  - 提供登出入口（顶部栏），点击后服务端销毁会话
  - 登出后原会话凭证不可再访问 `/api/*`
  - 前端清除本地会话态并跳转登录页
- **优先级**：Must · **里程碑**：M1 · **依赖**：US-M1-01

## M2 · 流式 / 每日额度限流 / 用量日志

### US-M2-01 · 流式调用
- **作为** User
- **我希望** 用 `stream=true` 流式调用模型
- **以便** 体验不差于直连
- **验收标准**
  - `StreamingResponse` 逐块转发上游 SSE
  - 内容与直连一致（含 tool call 透传）
- **优先级**：Must · **里程碑**：M2 · **依赖**：US-M0-01

### US-M2-02 · 流式错误补发
- **作为** GW
- **我希望** 流中途上游报错时向客户端补发 OpenAI 错误 event
- **以便** 禁止静默断流导致客户端卡死
- **验收标准**
  - 上游流中断时，向客户端发送标准 OpenAI error event 后再结束流
  - 不出现"收到一半无后续"
- **优先级**：Must · **里程碑**：M2 · **依赖**：US-M2-01

### US-M2-03 · 客户端断开处理
- **作为** GW
- **我希望** 检测到客户端断开时主动 cancel 上游请求
- **以便** 避免悬挂连接与费用浪费
- **验收标准**
  - 监听 disconnect，cancel 上游
  - 不继续消耗上游 token
- **优先级**：Must · **里程碑**：M2 · **依赖**：US-M2-01

### US-M2-04 · 每日 token 额度限流
- **作为** Admin
- **我希望** 给 VK 设每日 token 额度，超限返回 `429` + `Retry-After`
- **以便** 控制成本风险
- **验收标准**
  - 计数器存 Redis，超限返回 429 且带 Retry-After
  - 额度单位 = token（非金额）；null=不限制
- **优先级**：Must · **里程碑**：M2 · **依赖**：US-M1-06

### US-M2-05 · 自然日重置
- **作为** GW
- **我希望** 每日额度按本地时区自然日（次日 00:00）重置
- **以便** 个人/小团队直观管理
- **验收标准**
  - Redis 计数 TTL 对齐本地时区次日 00:00
  - 跨日调用计数归零
- **优先级**：Must · **里程碑**：M2 · **依赖**：US-M2-04

### US-M2-06 · 用量落库与归因
- **作为** GW
- **我希望** 每次调用记录 vk_id/account_id/model/provider/tokens/status
- **以便** 成本可归因到 key 与账号
- **验收标准**
  - usage_logs 写入成功，索引覆盖 account_id / vk_id + 时间
  - 非 OpenAI token 标 `cost_is_estimated`
- **优先级**：Must · **里程碑**：M2 · **依赖**：US-M1-06

### US-M2-07 · 用量视图（自身 / 全局）
- **作为** User / Admin
- **我希望** 在控制台查看自身（User）或全局（Admin）用量
- **以便** 了解消耗
- **验收标准**
  - User 仅见自身 Key 用量（后端过滤，见 US-M1-05）
  - Admin 见全局聚合
- **优先级**：Must · **里程碑**：M2 · **依赖**：US-M2-06, US-M1-04

## M3 · 配额感知路由 / fallback / 缓存 / 成本报表

### 错误码映射（关键）

### US-M3-01 · 识别额度耗尽错误
- **作为** GW
- **我希望** 按 provider 错误 **code**（非仅 HTTP 状态）识别"额度耗尽"
- **以便** 准确标记，避免与限流 429 混淆
- **验收标准**
  - OpenAI `insufficient_quota`、DeepSeek `402 insufficient_balance`、通义 `QuotaExceeded`/`AccountBalanceInsufficient` 映射为 `QUOTA_EXHAUSTED`
  - 映射逻辑在 `errors.py`，MVP 覆盖这三家
- **优先级**：Must · **里程碑**：M3 · **依赖**：US-M1-12 · **测试重点**：mock 端到端

### US-M3-02 · 额度耗尽自动切换
- **作为** User
- **我希望** 主 provider 额度耗尽时请求自动 fallback 到同别名下一可用 provider
- **以便** 服务不中断、无感切换
- **验收标准**
  - 观测到 `QUOTA_EXHAUSTED` → 标 `quota_exhausted` + 跳过 + fallback
  - 返回结果正常，调用方无感
- **优先级**：Must · **里程碑**：M3 · **依赖**：US-M3-01

### US-M3-03 · 禁止误标记
- **作为** GW
- **我希望** 仅当错误 code 明确指示 quota 才标记，绝不因通用 429/5xx 推断
- **以便** 健康模型不被误排除（误标记率目标 ≈ 0）
- **验收标准**
  - 通用 429（限流）、5xx、超时均不触发 `quota_exhausted`
  - 健康指标"配额误标记率"≈ 0
- **优先级**：Must · **里程碑**：M3 · **依赖**：US-M3-01 · **测试重点**：健康模型误标用例

### 探活与手动重置

### US-M3-04 · 低频探活自动恢复
- **作为** GW
- **我希望** 后台周期（~10min，带冷却）对 `quota_exhausted` provider 发 tiny completion 探活
- **以便** 额度恢复后自动清除标记
- **验收标准**
  - 探活成功 → 标记清除回 healthy
  - 探活网络错不翻转为 `down`（配额与网络两维度分离）
  - 探活频率受限，避免自身消耗额度/触发限流
- **优先级**：Should · **里程碑**：M3 · **依赖**：US-M3-02

### US-M3-05 · 手动重置标记
- **作为** Admin
- **我希望** 在 Dashboard「近期异常」或 Provider 页一键重置被标 provider
- **以便** 误标或紧急恢复时人工干预
- **验收标准**
  - Dashboard「近期异常」列表展示被标 provider + 重置按钮
  - 重置后标记清除
- **优先级**：Must · **里程碑**：M3 · **依赖**：US-M3-02

### Fallback / 重试 / 熔断

### US-M3-06 · 可重试错误退避
- **作为** GW
- **我希望** 对超时/5xx/限流 429 重试 + 指数退避 + 抖动（≤2~3 次）
- **以便** 瞬时故障自愈
- **验收标准**
  - 禁止对 4xx（除 429）重试
  - 退避有上限，避免长尾
- **优先级**：Must · **里程碑**：M3 · **依赖**：US-M1-13

### US-M3-07 · 熔断
- **作为** GW
- **我希望** provider 连续失败率超阈值（如 50%/30s）短暂熔断
- **以便** 防重试风暴
- **验收标准**
  - 熔断期间跳过该 provider
  - 熔断自动恢复（半开探测）
- **优先级**：Must · **里程碑**：M3 · **依赖**：US-M3-06

### US-M3-08 · 全失败 502 明细
- **作为** User
- **我希望** 候选 provider 全不可用时收到 `502` + 各 provider 失败原因
- **以便** 分清是网关侧而非自身代码问题
- **验收标准**
  - 返回 502，body 含各候选失败明细
  - 错误可读、可定位
- **优先级**：Must · **里程碑**：M3 · **依赖**：US-M3-06

### 精确缓存

### US-M3-09 · 精确缓存命中
- **作为** GW
- **我希望** 对相同非流式请求（`model + 归一化 request_hash`）精确缓存命中直接返回
- **以便** 降本提速
- **验收标准**
  - 命中零上游成本，TTL 可配
  - 仅作用于非流式、确定性 prompt

## MVP 显式不做（Won't）

为避免开发期"顺手加上"导致超范围，下列明确不在 MVP（M0–M3）实现，后续择机评估：

- **自助改密 / 忘记密码**：个人/小团队由 admin 后台改口令即可，不做自助流程。
- **MFA（多因子认证）**：内部管理台，MVP 不做。
- **操作审计日志**：MVP 不记录 admin 操作轨迹；排障靠结构化日志，后续可加。
- **对外 API 文档门户**：网关兼容 OpenAI 规范，文档以 OpenAI 官方为准，不单独建门户。

> 若任一项被提出，需经 stakeholder 重新评估并写回 PRD 非目标与对应故事，不在本期静默纳入。
