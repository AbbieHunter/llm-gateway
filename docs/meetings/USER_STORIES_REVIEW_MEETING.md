## 🎬 讨论剧本

**PM**：用户故事地图 v0.1 过一下。这份是把 PRD+设计+架构拆成 40 条可执行故事。今天重点不是数数，是找三类问题：**粒度不对、有遗漏、优先级错配**。我先把第一个 Dev 肯定要提的坑抛出来——

### 议题 1：第一个管理员从哪来？（重大遗漏）

**Dev**：我扫了一遍 M1，US-M1-01 是"登录"，但**没人创建第一个管理员**——总不能让系统凭空有个 admin 账号吧？这是个真缺口，不补 M1 起不来。

**PM**：好眼力，这是我漏的。个人/小团队场景，最干净的做法是**首次启动引导**：用环境变量（如 `BOOTSTRAP_ADMIN_PASSWORD`）或一条 setup 命令，在库里还没有账号时创建初始 admin。写一条新故事。

**用户**：别搞注册页啊，我一个人用，env 或命令初始化最省事。

**PM**：决议：**新增 US-M1-00「首次启动引导创建初始管理员」**，Must，M1 最先做，先于登录。

### 议题 2：优先级错配——熔断和客户端断开被低估

**Dev**：两个 Should 我觉得排低了。**US-M3-07 熔断**：PRD §4.4 明写"熔断防重试风暴"是核心要求，不是锦上添花，Should 低估了，应该 Must。

**QA**：我附议熔断。而且 **US-M2-03 客户端断开**也该升——开发者流式调用中途关页面，如果不 cancel 上游，真金白银的 token 还在烧。用户最在意这个。

**用户**：对，断流还继续花钱这事我零容忍，必须做。

**PM**：两个都升 Must。决议：**US-M3-07 熔断 Should→Must；US-M2-03 客户端断开 Should→Must。**（顺带 US-M3-09 精确缓存保持 Should，它确实降本但非阻断。）

### 议题 3：US-M3-10 报表是个"复合故事"，该拆

**QA**：US-M3-10 写"按 Key / 模型 / 时间查看"，AC 里也列了三个维度。但这是三个独立可测的功能，我测一个维度得单独建用例。建议拆成三条，独立验收。

**Dev**：同意，拆了也更好排期——按 Key 和按模型可能先做，按时间筛选后补。

**PM**：拆。决议：**US-M3-10 拆为 US-M3-10a（按 Key）、US-M3-10b（按模型）、US-M3-10c（按时间筛选）**，均 Must，M3。

### 议题 4：缺登出 / 会话失效故事

**QA**：US-M1-01 有登录，但没登出。Admin 在别人机器上登录后不登出，会话一直有效是安全隐患。

**Dev**：加个登出接口 + 前端按钮，顺手。

**PM**：决议：**新增 US-M1-14「登出与会话失效」**，Must，M1。

### 议题 5：配额感知路由怎么测？确认 mock 策略

**QA**：US-M3-01/02/03 都标了"mock 端到端"，但得定怎么 mock。"额度耗尽"不能真去烧一家 provider 的 quota 来验证吧？

**Dev**：对，真烧不现实也不可重复。我建议在测试里**起一个假的 provider 端点（或 WireMock）**，按错误 code 返回 `insufficient_quota` / `402 insufficient_balance` / 通义对应 code，网关照常走 `errors.py` 映射。误标记用例就用"返回 429 但 code 是限流而非 quota"来验。**真实 key 只在集成环境偶尔手测。**

**PM**：锁定这个策略：单测/集成测试全用 mock provider，错误 code 维度覆盖 OpenAI/DeepSeek/通义三家；误标记用例以"通用 429 不触发 quota_exhausted"为核心。QA 主导建这个 mock。

### 议题 6：SPA 空壳进 M0 值不值

**Dev**：US-M0-02 让 M0 就托管 SPA 空壳。其实 Vite build + FastAPI StaticFiles 是几行事，顺手验证"单进程托管"成立，早做早排雷，我支持保留。

**用户**：只要别在空壳上花时间做样式就行，占位即可。

**PM**：保留，明确"占位、不投入样式"。

### 议题 7：Won't 清单要显式写出来

**PM**：文档只有优先级没列"明确不做"。小团队 MVP 我建议显式砍掉：忘记密码/自助重置口令、MFA、操作审计日志、对外 API 文档门户。这些容易在开发时被"顺手加上"导致超范围。

**QA**：审计日志其实排障有用……但 MVP 先不做，后面加也不破坏结构。

**用户**：都同意砍，我不需要那么重。

**PM**：决议：**新增「MVP 显式不做（Won't）」清单**：自助改密/忘记密码、MFA、操作审计日志、对外 API 文档门户。记进文档。

### 议题 8：故事要不要估算

**Dev**：过审后进排期，每条得有个 T 恤尺码（S/M/L）才能拆 sprint。这份文档没估。

**PM**：估算不写进故事地图本身，作为下一步 planning 动作。决议：**故事地图保持"内容+优先级+依赖"，估算在 M1 启动前由 Dev 标注 T 恤尺码。**
